# Personal Dashboard 프로젝트 계획

## 목표
모바일 개인 대시보드(홈·금융·뉴스·혜택·일정)를 지금 화면 구성 그대로 유지하면서, 데이터 수신·저장·테스트를 다시 만들어 실제로 믿고 쓸 수 있는 상태로 만든다. 개발은 ai-orchestrator 엔진(계획 Issue → 구현 → 검수 → 반영)으로만 한다.

## 원칙
- **실데이터는 Supabase에만.** 이 저장소는 공개이므로 코드·문서·Issue·PR에 실명, 금액, 가맹점, 카드·승인번호를 절대 쓰지 않는다. 예시와 테스트는 가짜 데이터만 쓴다.
- **AI는 운영 DB에 접근하지 않는다.** 테스트와 화면 확인은 개발용 Supabase(가짜 데이터)로만 한다.
- **데이터는 API로만 받는다.** 피클AI는 `POST /api/ingest`로만 보내고, GitHub Issue로 데이터를 주고받지 않는다.
- 화면 구성(탭·카드 구성)은 유지하고, 디자인은 바뀔 수 있다.

## 구조
```
피클AI ──POST /api/ingest──▶ Vercel 운영계 ──▶ Supabase 운영 DB (실데이터, RLS)
사용자 폰 ── 로그인 ─────────▶ Vercel 운영계
AI 에이전트·CI ─────────────▶ Vercel 개발계 ──▶ Supabase 개발 DB (가짜 데이터)
```

## 단계
| 단계 | 내용 |
| --- | --- |
| 1 이사 | private_dashboard 코드만 기록 없이 이전, 실데이터 문서 제거 (완료) |
| 2 엔진 설치 | 엔진·워크플로, 개발 규칙, CI(타입·테스트·빌드·개인정보 패턴 검사), 비밀값 |
| 3 상황판 연결 | ai-orchestrator 상황판 `ORCH_REPOS` 등록, 홈에 에이전트별 진행 작업 표시 |
| 4 진단 | 현재 코드 점검 보고서 (살릴 것·다시 만들 것·지울 것) |
| 5 재정비 | 수신 API 재설계, 개발 DB 연동 테스트, 화면 정리, 배포 분리 |
| 6 전환 | 피클AI API 전환, 기존 저장소 삭제 |

## 이사 당시 상태 (2026-11-23)
- 타입 검사 통과, 단위 테스트 80개 통과 (Node 41, Python 39)
- 빌드·배포 검증, 실제 Supabase 연동 테스트, 화면 테스트 없음
- 일회성 API(backfill·reconcile·stage)와 데모 화면·데이터가 섞여 있음
- private_dashboard의 미반영 PR #9~11(수신 검증, 서버 스테이징)은 코드를 옮기지 않고 5단계 계획에서 다시 설계
