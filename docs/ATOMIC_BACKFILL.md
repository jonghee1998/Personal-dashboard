# Atomic metadata-only backfill (deployment pending)
This migration creates a private batch/audit table and service-role-only SQL functions. It does not modify existing dashboard rows on installation. No ingest behavior changes, no auto-publish, no migration execution from this commit.

1. Collector reruns /api/backfill/preview with the current full visible inventory. An earlier preview result is not permanent; new transactions or edits require a new plan. Stage via POST /api/backfill/stage with the same entries and expected_plan_digest. Staging stores the database snapshot and allowlisted patch candidates privately. No dashboard data changes. The SQL inventory RPC includes hidden/archived transactions for concurrency guards. Preview and stage use the same SQL inventory RPC after migration; the old read path is only a compatibility fallback before that RPC exists. Rerun preview after migration.
2. Owner reviews GET /api/backfill/control (authenticated user session; no collector token), summary, exact digest, count and source evidence. Explicit owner approval required; do not set BACKFILL_APPLY_ENABLED until migration and isolated tests pass. POST /api/backfill/control action apply, batch_id, plan_digest, expected_count, confirmation APPLY_METADATA_ONLY, same origin. No approval via Github comment/collector.
3. SQL locks dashboard_items against concurrent writes, compares complete current transaction snapshot with stored snapshot, checks row versions, patch keys and identity collisions, merges metadata only, checks business fields unchanged, records exact before/after and status in same transaction. Any error rolls back entire batch. Staged batches expire after 24 hours.
4. Rollback uses action rollback, batch_id, plan_digest, confirmation ROLLBACK_METADATA_ONLY. It preflights exact after-images of all changed rows. Any later user edit blocks rollback; unrelated new transactions are preserved. Restores metadata only, updated_at reflects rollback. No delete/reinsert. Audit data is private, retention/secure backup policy pending.
5. Re-run source reconciliation, verify unchanged IDs, amounts, dates, memos and counts for the applied scope. Fingerprint multiset and independent evidence remain separate; structurally eligible rows are not proof of absolute source authenticity.

Limits: table-wide lock during short apply/rollback briefly serializes all dashboard writes; normal ingest outside this operation unchanged. DB integration tests and actual migration not yet run. Apply remains disabled by default. No manual deployment until requested. Stage/apply user UI is not yet implemented; GET/POST are API only. No production data has been changed.
